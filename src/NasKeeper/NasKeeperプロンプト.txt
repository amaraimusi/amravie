
# 開発依頼：NasKeeper — NASバックアップ管理ツール

## 1. プロジェクト概要

**英語名：** NasKeeper  
**和名：** NASバックアップ管理ツール  
**開発言語：** Python 3.9  
**動作環境：** Windows 10 / 11  
**バックアップ先：** NAS（SMB共有フォルダー）

Windows PCからNASへファイルをバックアップするPython製のツールを開発してください。

Windowsエクスプローラーで大量のファイルをコピーすると、ファイルアクセスエラーや確認ダイアログが発生し、そのたびに処理が停止する問題があります。

夜間に長時間のバックアップを実行することが多いため、完全な無人実行を目指します。

最重要要件は、**個々のファイルでエラーが発生しても、バックアップ処理全体を停止させないこと**です。

また、ユーザーが途中でツールを終了しても、再実行時に未完了のバックアップ処理を再開できるようにしてください。

単なるコピー処理ではなく、安全性、再開性、ログ管理、差分バックアップを備えた実用的なツールとして完成させてください。

---

## 2. バックアップ対象

主なバックアップ対象は以下です。

- MP4動画
- 画像ファイル（JPG、PNGなど）
- 音声ファイル（MP3、WAVなど）
- その他の一般的なファイル

MP4ファイルが比較的多く、大容量ファイルも含まれます。

ただし、100GBを超えるような巨大な単一ファイルは基本的に想定していません。

ファイルの拡張子による制限は設けず、指定された保存元ディレクトリ以下のすべてのファイルをバックアップ対象にしてください。

サブディレクトリも再帰的に探索し、保存先では元のディレクトリ構造を維持してください。

## 3. 基本引数

必須引数は以下の2つです。

1. 保存元ディレクトリ
2. 保存先ディレクトリ

実行例：

```bat
python naskeeper.py "E:\backup_kenji\mov\amaraimusi_no_utabako" "\\LS710D567\webaxs\kenzy\mov\amaraimusi_no_utabako"
```

### 保存元ディレクトリ例

```text
E:\backup_kenji\mov\amaraimusi_no_utabako
```

### 保存先ディレクトリ例

```text
\\LS710D567\webaxs\kenzy\mov\amaraimusi_no_utabako
```

パスには日本語、空白、記号が含まれる可能性があります。WindowsのパスとUNCパスを正しく扱ってください。

指定された保存元ディレクトリそのものではなく、**その内部のファイルとディレクトリを保存先ディレクトリ以下へコピー**してください。

引数が不正な場合は、分かりやすいエラーメッセージを出力してください。

## 4. 最重要機能：途中で止まらないバックアップ

以下のエラーが発生しても、原則としてバックアップ処理全体を停止しないでください。

- ファイルが使用中
- アクセス権限がない
- ファイルが読み取れない
- NASとの通信が一時的に切断された
- ネットワークタイムアウト
- コピー途中で書き込みが失敗した
- コピー元ファイルが削除された
- コピー元ファイルが処理中に変更された
- NASの空き容量不足
- ファイル名やパスの問題
- その他のファイル単位の例外

### エラー発生時の基本処理

1. エラー内容をログに記録する。
2. 一時的なエラーであれば再試行する。
3. 再試行しても失敗する場合、そのファイルを保留またはスキップする。
4. 処理できる別のファイルがあれば続行する。
5. 失敗ファイルは後から再試行できるようにする。
6. すべての処理後に失敗ファイルの一覧を表示する。

エラー時に確認ダイアログやキーボード入力待ちを発生させないでください。

ただし、NAS全体への接続が失われた場合は、ファイルを次々と失敗扱いせず、接続が復旧するまで一定間隔で再接続を試みる仕組みにしてください。

再接続の待機時間や最大試行回数はオプションで変更できるようにしてください。

NASの容量不足など、再試行しても改善しない問題については、無限ループを避け、安全に停止または保留できる設計としてください。

---

## 5. 最重要機能：バックアップの中断と再開

ツールを途中で終了した場合でも、次回起動時にバックアップを再開できるようにしてください。

例えば以下のような状況です。

- 500ファイル中、300ファイルのバックアップが完了した。
- 301番目のファイルをコピーしている途中でツールを終了した。
- 翌日に同じコマンドでツールを再実行した。

この場合、正常にコピー済みの300ファイルを再コピーせず、301番目以降のバックアップを進めてください。

### 大容量ファイルの途中再開

可能であれば、ファイル単位だけでなく、ファイル内部の転送位置から再開できるようにしてください。

例えば40GBのMP4ファイルを30GBまでコピーした時点で終了した場合、次回は残り10GBから転送を再開できる仕様が理想です。

実装方法は任せますが、以下を守ってください。

- コピー途中のファイルは、一時的な拡張子などで区別する。
- 正常にコピー完了するまで正式なファイル名にしない。
- 再開前にコピー元のサイズ、更新日時、識別情報を確認する。
- コピー元が変更された場合、古い部分ファイルを無条件に再利用しない。
- 再開位置付近のデータを検証する。
- 保存済みの転送位置を信用するだけでなく、NAS上の実ファイルの状態も確認する。
- コピー完了後、検証を行って正式ファイルに切り替える。
- 一時ファイルが破損している場合は、安全な位置から再転送する。

Pythonプロセスの通常終了、Ctrl+C、異常終了、PCの強制終了、ネットワーク切断を想定してください。

ただし、すべての障害から必ずバイト単位で再開できるとは限らないため、安全性を優先し、必要に応じて当該ファイルを最初からコピーし直してください。

## 6. バックアップ状態の保存

保存先ディレクトリ内にバックアップ管理データを保存して構いません。

SQLite、JSON、CSVなどを検討し、最も適切な方式を採用してください。

推奨はSQLiteです。

管理データには以下の情報を保持してください。

- コピー元ファイルの相対パス
- 保存先ファイルの相対パス
- ファイルサイズ
- コピー元の更新日時
- バックアップ完了日時
- 処理状態
- 再試行回数
- エラー内容
- 転送済みサイズ
- 検証済み再開位置
- 必要なファイル識別情報

### 保存場所の例

```text
\\LS710D567\webaxs\kenzy\mov\amaraimusi_no_utabako\
    .naskeeper\
        state.sqlite
        logs\
        temp\
```

ただし、SQLiteをNAS上へ直接配置すると、SMB接続切断時にデータベースの更新処理が失敗する可能性があります。

そのため、以下の方式を比較検討してください。

**方式A：NAS上にSQLiteを直接保存する**

**方式B：PCローカルにSQLiteを保存し、NAS側にも復旧用の管理データを保存する**

安定性と、別PCからの復旧可能性を考慮して適切な方式を採用してください。

特に、管理データの書き込み途中で通信が切れた場合でも、バックアップ済みファイルが失われない構造としてください。

管理データが消失・破損した場合には、保存先を再スキャンして状態を再構築できるようにしてください。

なお、管理用の`.naskeeper`ディレクトリはバックアップ対象として扱わないでください。

## 7. 差分バックアップ

バックアップは毎回すべてをコピーするのではなく、基本的に差分バックアップとしてください。

### 基本ルール

- 保存先に存在しないファイルはコピーする。
- 保存先に存在し、サイズと更新日時が一致するファイルはスキップする。
- コピー元が更新されている場合は再コピーする。
- コピー元から削除されたファイルが保存先に残っていても削除しない。
- 不明な状態のファイルは安易に上書きしない。

**バックアップ元のファイルを削除・変更する処理は絶対に実装しないでください。**

保存先のファイルについても、通常モードでは削除しない設計としてください。

既存ファイルを更新する場合は、新しいファイルの転送・検証が正常に完了するまでは古い正常ファイルを保持してください。

旧版の世代保存を行うかどうかはオプションで選べるようにしてください。初期設定では安全性を優先してください。

## 8. 非同期処理と転送速度

Python 3.9で実装してください。

大容量のMP4ファイルが多いため、むやみに並列数を増やす必要はありません。

初期設定は1ファイル転送、オプションで2～4並列を指定できるようにしてください。

Python標準ライブラリの`concurrent.futures.ThreadPoolExecutor`などを利用しても構いません。

`asyncio`を利用する場合も、通常のファイルI/Oが自動的に非同期化されるわけではない点に注意してください。

実装方式の選択理由をREADMEに記載してください。

### 転送方式

- 大容量ファイルをメモリに一括読み込みしない。
- 一定サイズのバッファで逐次読み書きする。
- バッファサイズをオプション指定できるようにする。
- 初期値は1MiB程度とする。
- 進捗更新やログ出力が転送性能を過度に低下させないようにする。
- データの書き込み完了と検証を確実に行う。
- 転送速度の平均値を計測する。

複数ファイルを並列転送するときは、SQLite更新処理の競合や、同一ファイルへの多重書き込みが発生しないようにしてください。

最初は安全性を優先し、並列数1でも十分実用的な構造としてください。

## 9. ログ出力

画面表示とログファイルの両方に対応してください。

ログには以下を記録してください。

- 実行開始日時
- 保存元ディレクトリ
- 保存先ディレクトリ
- コピー対象ファイル数
- コピー成功ファイル
- スキップファイル
- コピー失敗ファイル
- エラーの原因
- 再試行回数
- 処理時間
- 転送データ量
- 平均転送速度
- 実行終了日時

ログはファイル単位で記録しつつ、通常の画面表示は簡潔にしてください。

エラー発生時には、対象ファイルと失敗原因が分かるようにしてください。

- ファイルの転送進捗率
- 現在の転送速度

## 11. コマンドラインオプション

必須引数は2つのみとし、その他はオプションとしてください。

推奨オプション：

```text
--workers N
    同時転送数。初期値1。

--buffer-size SIZE
    転送バッファサイズ。

--retry N
    ファイル単位の最大再試行回数。

--retry-wait SEC
    再試行待機時間。

--resume
    中断済み処理の再開。
    初期設定で有効。

--verify MODE
    検証レベル。
    size / hash など。

--dry-run
    実際にはコピーせず、処理内容だけ確認。

--log PATH
    ログ出力先。

--state-dir PATH
    状態管理データの保存先。

--version
    ツールのバージョンを表示。

--help
    ヘルプを表示。
```

必要に応じて他の便利なオプションを追加しても構いません。

`--resume`は初期設定で有効にするため、明示的な指定なしでも再開できるようにしてください。

## 12. 安全性と異常終了への対応

以下の条件を満たしてください。

1. コピー元データは読み取り専用として扱い、変更・削除しない。
2. コピー途中のファイルを正常完了扱いにしない。
3. 保存先に存在する正常なファイルを、未完了のファイルで破壊しない。
4. 通信切断時の部分ファイルを適切に管理する。
5. 途中終了後に再実行しても整合性が壊れない。
6. 容量不足時に無限リトライしない。
7. 同一ジョブの二重起動を防止する。
8. コピー元とコピー先が同一、または再帰的に包含される場合は誤動作を防ぐ。
9. シンボリックリンクやジャンクションによる循環探索を防ぐ。
10. NASの応答が停止した場合のタイムアウト、再試行、終了方針を明確にする。
11. Pythonプロセスの強制終了に備え、状態管理データを定期的に確定する。
12. 管理情報に絶対パスを保存する場合も、復元やNAS変更時に柔軟に対応できるようにする。
13. NAS上での最終ファイル名への変更操作に失敗した場合も復旧可能にする。
14. 管理用ファイルや一時ファイルを通常のバックアップ対象と混同しない。

なお、ユーザー操作による通常終了とCtrl+Cでは、可能な限り安全に書き込みを終えて状態を保存してください。

強制終了や停電では正常終了処理が実行できないため、起動時の復旧ロジックで対応してください。

## 14. テスト

完成後、以下の動作テストを必ず行ってください。

### 基本テスト

- 単一ファイルのコピー
- 複数ファイルのコピー
- サブディレクトリの再帰コピー
- 日本語ファイル名
- 空白を含むファイル名
- 空ディレクトリ
- 同名ファイルが異なるサブディレクトリにある場合
- 保存先に既存ファイルがある場合
- 差分バックアップ

### 再開テスト

- コピー途中で通常終了する。
- Ctrl+Cで処理を中断する。
- 大容量ファイルの途中から再開する。
- 部分ファイルが壊れている場合に安全に対処する。
- コピー元ファイルが変更された場合に不正な再開をしない。
- 状態管理データが失われた場合に復旧できる。

### エラーテスト

- コピー元ファイルが消える。
- コピー元ファイルがロックされている。
- 保存先の書き込み権限がない。
- NASへのアクセスができない。
- 書き込み途中に例外が発生する。
- NAS容量が不足する。
- 複数ファイルのうち一部だけが失敗する。

エラーが起きても、そのほかの正常なファイルの処理を継続できることを確認してください。

### 大容量ファイルテスト

数GB程度のテストファイルを使い、メモリ消費量、転送速度、中断再開の正常性を確認してください。

テスト用ファイルの生成では必要以上にディスク容量を消費しないようにしてください。

実際のNASへの接続テストが実行環境でできない場合は、ローカルフォルダーで代替テストを実施し、NAS実機での未検証項目を明記してください。
