NasKeeper — NASバックアップ管理ツール

Windows PCからSMB共有へ、元の構造を維持して安全にバックアップするコマンドラインツールです。コピー元を変更・削除しません。GUIや確認入力、追加パッケージは不要です。

動作環境・導入

Windows 10 / 11、Python 3.9以上。標準ライブラリのみを使用します。ZIPをPCのローカルフォルダーに展開してください。

cd /d C:\Users\user\git\amravie\src\NasKeeper
python naskeeper.py --help
python naskeeper.py --version

基本的な使い方

保存元フォルダーの中身をコピーします。拡張子の制限はありません。日本語、空白、UNCパスは引用符で囲んでください。

python naskeeper.py "E:\backup_kenji\mov\amaraimusi_no_utabako\a001" "\\LS710D567\webaxs\kenzy\mov\amaraimusi_no_utabako\a001" --dry-run
python naskeeper.py "E:\backup_kenji\mov\amaraimusi_no_utabako\a001" "\\LS710D567\webaxs\kenzy\mov\amaraimusi_no_utabako\a001"

初期設定は1並列、1MiBバッファ、SHA-256検証、再開有効、旧版保存有効です。Ctrl+Cで中断し、同じコマンドで再実行します。失敗・保留ファイルも次回再試行します。

差分バックアップ・データ保護

存在しないファイルを転送します。サイズ・更新日時が一致すればスキップし、既定のhashモードでは内容も照合します。同一の既存ファイルは検証後に管理対象へ取り込みます。hashモードでは同じサイズ・日時でも内容が異なる場合に保留または再転送を行います。

更新時はNAS側の復旧記録と既存ファイルのSHA-256を照合します。由来や整合性が確認できない既存ファイルは上書きせず保留します。必要なバックアップを別の場所へ退避してから再実行してください。転送中に既存バックアップが変更された場合も保留します。

コピー元から消えたファイルもNASに残ります。通常ファイルを削除する同期・ミラー機能はありません。新ファイルの転送・検証・旧版保存が完了してから正式ファイルを置換します。

旧版は .naskeeper/versions/<識別子>.bak に保存し、同名のJSONに元の相対パスを記録します。旧版は追加容量を消費し、自動削除しません。

中断・再開

NASの .naskeeper/temp に識別子付き.partとJSONを作ります。サイズ、ナノ秒更新日時、device/inode、相対パス、保存元ルートを記録し、再開時に照合します。変更があれば古い部分ファイルを利用せず最初から再送します。

識別情報が一致しても、部分ファイル全体を元ファイルとバッファ単位で比較し、最初の不一致ブロックより前だけを再利用します。DBの保存位置だけを信用せず、NAS上の実サイズと内容を確認します。全体照合はNASからの読み取りが必要で、送信量が減っても検証時間がかかります。

5秒間隔と中断時にflush/fsyncとDB確定を実施します。転送後にサイズ、既定ではSHA-256、元の識別情報を再確認し、同じNAS内でos.replaceにより正式名へ切り替えます。NASのキャッシュや停電への耐久性は機器側の実装にも依存します。

置換に失敗しても部分ファイルを保持します。置換前にpending復旧記録を保存するため、置換直後の管理更新に失敗しても次回に実ファイルのハッシュから復旧できます。元が転送中に変わると完成扱いにしません。録画や編集が終了したファイルを対象にしてください。OSスナップショットは取得しません。

状態管理・ログ

方式A（NAS上SQLite）は切断やSMBロック実装の影響を受けます。本ツールは方式Bを採用し、SQLiteをPCローカルに保存し、NASにも復旧情報を残します。

- 既定のDB: %LOCALAPPDATA%\NasKeeper\<保存先識別子>\state.sqlite

- UTF-8ログ: 同じフォルダーの logs\日時-PID.log

- NAS: .naskeeper/receipts の完了・pending記録、tempの部分ファイルと識別情報、versionsの旧版

SQLite更新はロックで直列化し、1ファイルの多重転送を防ぎます。ログに開始・終了日時、対象、成功、スキップ、失敗、原因、再試行、転送量、経過時間、平均速度を記録します。画面進捗は最大毎秒1回。ファイル名、進捗率、速度、件数、経過、残りの目安、エラー数を表示します。残り時間は転送速度に基づく目安で、検証・旧版保存時間は正確に予測しません。

DBが破損すると state.corrupt.<識別子>.sqlite へ退避します。次回起動では元の一覧とNASの実ファイル・復旧記録からDBを再構築します。両側の管理情報がなくても元と同一と確認できた完成ファイルは取り込めます。異なる既存ファイルは保留します。保存先変更時も同じ方式で取り込めます。別PCで元のパスが異なる場合は同一内容を取り込んでから更新してください。

PCとNASのOSファイルロックで同じ保存先の二重起動を防ぎます。ロックファイルは削除しないでください。SMBサーバーがバイト範囲ロックを提供する必要があります。ネットワーク分断・サーバー再起動をまたぐ複数PCの完全な排他は保証できません。同じ保存先には一台のPC・一つのスケジュールを使用してください。

エラー・応答停止の方針

ファイル単位のアクセス拒否、削除、破損、競合はログに残してほかのファイルへ進みます。共有違反、一時的I/Oエラー、ネットワーク系エラーは指定回数だけ再試行します。権限エラーや不明な既存ファイルを無限再試行しません。

保存先ルートに到達できなければ共有の接続待機ゲートで新規処理を止め、指定間隔と回数で復旧を待ちます。復旧しないと未着手ファイルを保留して終了します。NAS内の一部フォルダーだけの権限問題は個別の失敗扱いです。空き容量不足はジョブ全体の新規処理を止め、次回再開します。

Pythonの通常ファイルI/OにはSMB呼び出しを確実に中断するタイムアウトがありません。OSの応答待ちでも、別の監督プロセスが既定12時間の上限で子を強制終了します。max-runtimeはジョブ全体の上限で、個々のI/Oのタイムアウトではありません。夜間の実行枠に合わせて調整してください。0を指定するとOSの待機が長時間続く可能性があります。再接続待ち時間・回数は各OS呼び出しが戻った後に適用されます。

Ctrl+Cは中断フラグを立ててバッファ境界で保存します。監督プロセスは10秒待って応答しない子を停止します。時間上限、強制終了、停電では終了処理を保証できないため次回に実データを検証します。

Windowsタスクスケジューラ

「基本タスクの作成」で毎日の時刻を設定します。

1. プログラムに実際のPython 3.9のpython.exeの絶対パスを指定。

2. 引数に "C:\Users\user\git\amravie\src\NasKeeper\naskeeper.py" "保存元" "\\NAS\共有\保存先" --quiet --max-runtime 28800 を指定。

3. 開始フォルダーに C:\Users\user\git\amravie\src\NasKeeper を指定。

4. 「既に実行中の場合」は「新しいインスタンスを開始しない」。

5. 同じアカウントでNASのUNCパスを開けることを確認。

6. 短いテストを実行し、ログ・終了コードを確認。

資格情報をコマンドやログへ記録する機能はありません。無人実行アカウントがアクセスできるUNCパスを使い、ドライブ割り当てに依存しないでください。

復元

完成ファイルはNASの通常ファイルです。必要なものを別の復元用フォルダーへコピーしてください。tempの.partは未完成なので使いません。旧版はversionsのJSONで相対パスを確認し、対応する.bakを別フォルダーへコピーして元の名前にします。

トラブルシューティング・制限

- 接続不可: 同じWindowsアカウントでエクスプローラーからUNCパスを確認。

- 容量不足: 新ファイルと旧版分の空きを確保して再実行。

- 既存ファイル保留: 由来・内容を確認し、必要なら別の場所へ退避。

- 時刻精度の異なるNAS: mtime許容秒を明示指定できますがsizeモードの精度は下がります。

- 保存元・保存先の同一・包含は禁止。リンク、ジャンクション、reparse point、管理用.naskeeperは探索しません。

- ハッシュ検証で両側の全データを読みます。ファイル一覧はメモリに保持しますが内容はバッファで逐次処理します。

- 内容と更新日時が対象です。ACL、所有者、代替データストリーム、ハードリンク構造、特殊デバイスは対象外。VSSは使いません。

- 長いパス、禁則文字、最大パス長はOS・NASの環境依存です。扱えないファイルは個別に記録。

- 外部ツールとの同時書き込みは避けてください。悪意ある外部変更やファイルシステム競合を完全に隔離する機能はありません。

- 同期ファイルI/OをThreadPoolExecutorで処理します。asyncioだけでは通常のファイルI/Oが非同期にならないため採用していません。

テスト

python -m unittest discover -s tests -v
set NASKEEPER_LARGE_TEST=1
python -m unittest discover -s tests -p test_large.py -v

大容量テストは2GiBのスパース元ファイルを作り、実プロセスを強制終了してから再開・ハッシュ照合・メモリ計測します。保存先用に最低約2GiBの空きが必要です。一時フォルダーはwork配下に作成し、終了時に片付けます。実測結果と実NASの検証状況はTEST_REPORT.mdを参照してください。
